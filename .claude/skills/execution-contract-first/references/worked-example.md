# Worked Example — 실제 세션 재현

실제로 있었던 작업 세션. 미련한 지시 → 3번의 푸시백 → 뒤늦은 정렬로 흘러갔다.
이 스킬이 있었다면 푸시백 전부가 작업 시작 전 5줄 정렬에서 잡혔어야 한다.

## Case 1 — 퍼널 문제 정의

### 원본 지시 (실제)

> "광고가 /start로 연결되는데 담당자가 '들여보내는 건 되는데 이후 앱/웹으로
> 이어지는 깔끔한 파이프라인이 안 된다, 질문 4개 제한은 depth가 너무 낮다'고
> 계속 말함. 이게 뭔지 정의부터 하고 15분 웹 조사하고 어떻게 할지 정하자."

### 실제로 일어난 실패

1. AI가 화면을 한 번도 안 밟고 "post-click activation bridge" 문제로 정의
   → 푸시백 1: "그게 안 이어지는지 어떻게 알아?"
2. 사용자를 "차분히 사건 정보를 입력하는 사람"으로 가정
   → 푸시백 2: "이 사람들은 신고당해서 공포 상태라고"
3. AI 자신의 관심사(웹→앱 데이터 연속성)를 사용자의 관심사로 착각
   → 푸시백 3: "너가 중요하다고 생각하는 게 중요한 게 아니라고.
   화면 게이트 뜰 때까지 직접 다 해보고 말해"

### 스킬이 물었어야 할 질문 (2개면 충분)

1. "판단 기준이 되는 사용자상부터 — 이 페이지에 들어오는 사람은 어떤
   심리 상태야? 차분하게 정보 찾는 사람이야, 신고·체포 직후 패닉 상태야?"
2. "정의가 맞았는지는 뭘로 판정할까 — 내가 화면을 게이트까지 직접 밟고
   각 화면 보고를 붙이는 걸 전제로 할게. 그 외 추가 기준 있어?"

### 재작성된 프롬프트 (정렬 후)

```
[목표] 담당자가 말한 "파이프라인 없음 / depth 낮음"의 진짜 문제를 정의하고,
재설계 방향을 결정할 수 있는 상태까지.

[첫 행동 / 증거 규칙] /start를 광고 유입 → 4질문 → 게이트 → 스토어까지
직접 끝까지 밟고, 각 화면에서 본 것을 먼저 보고한다. 그 전에는 정의하지 않는다.
안 해본 것은 안 해봤다고 쓴다.

[판단 기준] 사용자는 신고당해 "오늘 잡혀가나, 감옥 가나" 상태인 사람.
모든 판단은 이 사람 머릿속 질문 기준. AI가 중요하다고 보는 것은 기준이 아니다.

[리서치 기준] 15분, 여러 주제 교차, 주장마다 출처. 일반론은 0점.

[진행 규칙] 실물 확인 후 문제 정의 + 완료 기준 5줄을 먼저 제출하고,
컨펌 받고 진행한다.
```

## Case 2 — 전문가 AI 룰북

### 원본 지시 (실제, 요약)

> "범용 AI 답변('침착해라, 변호사 찾아라') 말고 진짜 경험에서 나온 조언을
> 하는 전문가 AI 프롬프트 룰북을 만들어야 함. 라우팅해서 상태 분리하고
> 룰북에서 찾아 답하게. 조사는 히스 레저가 조커 연구하듯 메소드 연기 수준으로."

### 실제로 일어난 실패

- AI가 DV(가정폭력) 한 갈래만 다룬 룰북 문서를 만들고 "완성했다"고 보고
- 푸시백: "완료가 된 거임? DUI·마약소지도 있는데. 완료 기준을 엄격히 잡고,
  별도 로컬 세션에 룰북을 넣어 테스트·평가까지 해야지. 룰북 만들라고 했으니
  룰북만 만들면 되는 게 아니란 말이지"

### 스킬이 물었어야 할 질문 (2개)

1. "지원 범위 — 1차로 DV만 깊게 갈까, DUI·마약소지까지 라우팅에 넣을까?
   (안 넣는 범죄군은 '미지원'으로 선언하고 아는 척 안 함)"
2. "완료 판정 — 별도 세션 블라인드 테스트 + 독립 채점으로 잡을 건데,
   통과선(예: 케이스당 9/10 이상, critical fail 0)과 회귀까지 포함할까?"

### 재작성된 프롬프트 (정렬 후)

```
[목표] 룰북 문서가 아니라, 별도 세션에서 범용 AI를 이기는 게 증명된
전문가 엔진. 룰북은 그 부품.

[판단 기준] 첫 형사사건으로 극도로 불안한 사용자. "침착해라" 류 일반 문구가
나오면 그 답변은 실패.

[완료 기준] 범죄군(DV·DUI·마약소지) 라우팅 → 별도 세션 블라인드 테스트
→ 독립 채점 케이스당 9/10 이상 + critical fail 0 → 실패 원인 수정 →
변형 포함 회귀 → 전체 회귀 통과. 이걸 통과하기 전에는 "완성"이라는 단어 금지.

[증거 규칙] 요금·기한·절차 같은 수치는 전부 출처 확인. 틀린 통념은 교정해서
기록. 안 해본 검증은 안 했다고 명시.

[예시 한 쌍]
- 원하는 답: 감독 방문의 신청 창구, 실제 요금 범위, 감독관이 기록하는
  방식과 그 어색함까지 담긴 답
- 금지 답: "Stay calm. Contact a lawyer. 아이들을 위해 참으세요."

[진행 규칙] 실행 전에 문제 정의·완료 기준·검증 계획 5줄 제출 → 컨펌 → 시작.
```

## 이 예시에서 얻을 일반 원칙

- 푸시백은 대부분 "빠진 칸을 AI 기본값으로 채운 결과"다. 지시가 짧을수록
  기본값이 많이 들어가고, 기본값이 많을수록 재작업이 커진다.
- 질문은 많이 필요 없다. 위 두 케이스 모두 2개로 충분했다. 결과를 가르는
  칸(판단 기준, 완료 기준)만 정확히 찌르면 된다.
- "시야 넓게"의 실체는 완료 기준을 스스로 엄격하게 세우는 것이다.
  지시받은 산출물(룰북)이 아니라 목표(증명된 엔진) 기준으로 범위를 잡는다.
