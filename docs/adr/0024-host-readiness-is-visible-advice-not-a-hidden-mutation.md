# Host readiness is visible advice, not a hidden mutation

Inspect power source, idle-sleep protection availability, portable-Mac lid
risk, and selected-volume disk space when generating an overnight plan.

Do not modify macOS Energy settings, create wake schedules, clean storage, or
hold a power assertion before approval. The detached coordinator's existing
`caffeinate -i` wrapper begins only after exact approval.

Keep readiness advisory and repeat every warning in the portfolio approval.
The machine state can change after observation, and the app cannot infer the
operator's future lid or dock action. A warning therefore requires informed
operator judgment rather than silently removing work or pretending the host
is guaranteed to stay awake.
