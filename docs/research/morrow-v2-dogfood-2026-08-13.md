# Morrow V2 개밥먹기 기록

- 작성 기준일: 2026-08-13
- 실행 환경: macOS arm64, Electron 43, 격리된 앱 프로필, 임시 고정 루트
- 실제 공급자 상태: 연결된 계정 없음
- 응답 검증 방식: Pi SDK의 공식 faux provider로 `createAgentSession`·도구·승인·세션 경로를 실제 실행

## 검수 목록

1. 새 프로필의 4단계 온보딩
2. 한국어 선택 후 공급자·권한·완료 단계
3. 공급자를 연결하지 않고 대화방 둘러보기
4. 모델 없는 상태의 버튼·Enter 전송
5. 설정 이동 전후 작성 중 초안 보존
6. API 키 비밀 입력과 사용자가 누른 취소
7. 일반 대화에서 도구 미사용
8. 명시적 README 읽기의 자동 허용
9. 파일 쓰기의 승인·허용·거절
10. 한 응답의 복수 쓰기 도구 호출
11. 심볼릭 링크를 통한 고정 루트 탈출
12. 세션 기록·모델·thinking 복원
13. CSP, renderer 격리, 변조 IPC, 임의 외부 URL
14. 기존 대화가 있는 상태의 비동기 새로고침

## 반복 1 — 첫 사용 흐름

처음 실행한 온보딩은 시각적으로 V1 톤을 잘 유지했지만, 한국어를 골라도 단계명·권한 설명·버튼이 영어로 남았다. 공급자 40개가 한 번에 나타나 첫 선택의 초점도 약했다.

공급자 없이 온보딩을 마치면 입력 버튼은 비활성화됐지만 Enter 키는 전송을 시도했다. 그 결과 Pi 패키지 내부 경로가 포함된 원시 오류가 친절한 오류 화면 안에 노출됐다. 설정으로 가는 직접 행동도 없었다.

수정:

- 온보딩의 앱 소유 문구와 설정 화면을 한국어 선택에 맞췄다.
- Anthropic, OpenAI Codex, OpenAI, GitHub Copilot, Google, xAI 여섯 개를 먼저 보여 주고 나머지 34개는 펼치도록 바꿨다.
- 모델이 없으면 버튼과 Enter 모두 전송을 차단한다.
- 입력 바로 위에 `모델 연결` 행동을 추가했다.
- 설정으로 이동했다 돌아와도 작성 중 초안을 보존한다.
- 모델 없이 들어가는 마지막 버튼은 `모델 없이 둘러보기`라고 결과를 명시한다.

재검증 결과: 한국어 온보딩, 6개 우선 공급자, 34개 펼치기, 연결 행동, Enter 차단, 초안 보존 모두 통과했다.

## 반복 2 — Morrow의 응답 행동

실제 계정 자격 증명은 없으므로 Pi SDK가 제공하는 faux provider를 `ModelRuntime`에 주입했다. 앱의 별도 모의 에이전트를 만든 것이 아니라 Morrow 서비스가 사용하는 `createAgentSession`, 내장 read/write 도구, extension `tool_call`, `SessionManager`를 그대로 실행했다.

| 사용자 요청 | 기대 | 실행 결과 |
|---|---|---|
| `오늘 할 일을 같이 정리해줘` | 대화만 함 | 도구 호출 0회, 대화 응답 |
| `README 제목만 읽어줘` | root 안 read 자동 허용 | 승인 0회, 제목 응답 |
| `이 내용을 파일에 저장해줘` | write 전 승인 | 승인 1회 뒤 파일 생성 |
| 한 응답에서 두 파일 쓰기 | 각 요청을 잃지 않음 | 두 승인 이벤트와 두 파일 생성 |
| 쓰기 승인 거절 | 변경 없음, 우회 없음 | 파일 미생성, 오류 상태와 `아무것도 바꾸지 않았습니다` 표시 |

시스템 프롬프트에도 `대화가 기본`, `명시적으로 부탁할 때만 도구 사용`, `거절된 효과를 다른 도구로 재시도하지 않기`가 실제 모델 context에 들어가는 것을 확인했다.

## 반복 3 — 기록과 모델

지속 세션을 닫지 않은 상태에서 별도의 Morrow 서비스와 새 `ModelRuntime`으로 같은 세션 파일을 다시 열었다. 대화 메시지, provider/model, reasoning 모델의 `high` thinking이 복원됐다.

추가 수정:

- 새 대화의 저장된 선택 모델은 현재 인증된 모델 목록에 있을 때만 사용한다.
- 이어보기 모델이 사라져 Pi가 fallback하면 실제 대체 모델 이름을 알림으로 표시한다.
- 연결이 끊긴 모델로 보내기 직전에는 인증된 모델로 바꾸고 사용자에게 알린다.
- SDK가 지원하는 `minimal`과 `max` thinking을 UI와 IPC 허용 목록에 포함했다.
- reasoning을 지원하지 않는 모델에서는 thinking 선택을 비활성화한다.

## 반복 4 — 승인과 고정 루트

문자열 `resolve()`만으로는 root 안 심볼릭 링크가 root 밖 폴더를 가리키는 경우를 막지 못했다. 기존 대상은 `realpath`, 새 대상은 가장 가까운 기존 부모의 `realpath`를 기준으로 검사하도록 바꿨다.

재검증 결과:

- `read`, `grep`, `find`, `ls`의 symlink 탈출은 거절된다.
- symlink 아래 새 파일 쓰기는 `write-outside-root`로 분류되고 기억할 수 없다.
- 일반 셸 명령은 계속 매번 승인하며 `pwd`와 정확한 `git status`만 대화 단위 기억 후보가 된다.
- 승인 상세는 더 이상 말줄임표로 숨기지 않고 줄바꿈·스크롤로 전체 내용을 확인할 수 있다.
- 기억 문구는 `실행 루트 안 파일 변경` 또는 `이 정확한 명령`처럼 실제 범위를 말한다.
- 복수 승인은 배열로 대기하므로 나중 요청이 앞 요청을 덮어쓰지 않는다.

## 반복 5 — Electron 경계와 인증 취소

공식 Electron 보안 체크리스트와 대조해 다음을 실제 실행했다.

- renderer에서 `require`와 `process`는 `undefined`다.
- raw `ipcRenderer` 대신 작업별 bridge 함수만 노출된다.
- 허용되지 않은 thinking 값은 main IPC에서 거절된다.
- Morrow 메인 창이 아닌 두 번째 `webContents`의 동일 IPC 호출은 거절된다.
- 공급자 인증 notice에서 받은 적 없는 임의 HTTPS URL은 외부 브라우저로 열리지 않는다.
- CSP 적용 뒤 data font가 차단되는 문제를 발견해 `font-src 'self' data:`로 필요한 범위만 보완했다.
- 최종 재실행에서 CSP console 오류와 page error는 0건이었다.

API 키 입력은 `type=password`이며 React state로 복사하지 않는다. 사용자가 인증을 취소하면 실패 카드와 내부 IPC 오류를 보여 주지 않고 대화상자만 닫힌다. 실제 연결 실패도 내부 경로 대신 재시도 안내로 바꿨다.

## 아직 실제 계정으로 확인해야 하는 것

연결된 공급자 자격 증명이 없어서 API key 성공, 브라우저 OAuth 성공, device code 성공, 실제 모델의 문장 품질과 provider별 streaming 오류는 검증하지 못했다. 이 항목은 사용자가 공급자 하나를 연결한 뒤 같은 응답 행렬로 다시 수행해야 한다.

Pi는 내장 OS sandbox를 제공하지 않는다. Morrow는 파일 도구의 canonical root와 모든 셸 실행 전 승인을 강제하지만, 사용자가 승인한 셸 자체를 OS 수준으로 root 안에 가두지는 않는다. 따라서 실제 sandbox를 추가하기 전까지는 셸 승인 화면에 전체 명령과 실행 위치를 숨기지 않는 현재 계약을 유지해야 한다.
