# Support

God of Sessions is maintained on a best-effort basis. There is no guaranteed
response time, uptime commitment, or support contract.

## Where to ask

- Use a bug report for reproducible product defects that can be demonstrated
  with synthetic data.
- Use a feature request for a user problem or provider limitation that does not
  expose private provider data.
- Use repository Discussions for setup questions and general usage help when
  Discussions are enabled.
- Use GitHub's private **Report a vulnerability** flow for security issues.

Do not put credentials, transcripts, provider databases, absolute local paths,
private repository names, unredacted logs, or screenshots containing personal
data in a public issue.

## Provider support boundary

God of Sessions uses official provider runtimes. Authentication failures,
provider outages, rate limits, billing, and provider-owned account support
usually belong with the provider. A God of Sessions issue is appropriate when
the app misclassifies the provider state, weakens an approval boundary, or
misrepresents an unsupported route as ready.

## Useful bug-report details

Safe reports may include:

- God of Sessions version;
- operating system and CPU architecture;
- provider name and provider runtime version;
- expected and observed behavior;
- reproduction steps using a synthetic repository;
- redacted error category;
- whether the problem reproduces after a normal app restart.

If the report cannot be reproduced without private data, first open a minimal
issue asking a maintainer to establish an appropriate private channel.
